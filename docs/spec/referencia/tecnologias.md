# Tecnologias

Use exatamente esta stack, salvo se eu autorizar mudança:

- **Backend**: Node.js 20 ou mais novo, TypeScript em modo estrito, Fastify.
- **Frontend**: React com Vite e TypeScript, Tailwind para estilo, na versão estável atual, configurado conforme a documentação dessa versão, `react-router` para rotas, `@tanstack/react-query` para busca de dados, `class-variance-authority` para variantes de componentes, `recharts` para gráficos e `lucide-react` para ícones, instalados via npm. Regras completas no arquivo `docs/spec/referencia/interface-visual.md`.
- **Banco**: PostgreSQL com o driver `pg` e migrações em SQL puro versionadas numa pasta `migrations`. O acesso ao banco fica isolado numa camada de repositórios. Use transações sempre que houver controle de saldo de custo.
- **Autenticação**: sessão em cookie `httpOnly` e `sameSite=lax`, com `secure` em produção, usando `@fastify/cookie` e `@fastify/session` com as sessões **guardadas no PostgreSQL**, para sobreviverem a reinícios. Senhas com `argon2`, limitação de tentativas de login com `@fastify/rate-limit`.
- **Jev**: SDK oficial `@typesafe-ai/sdk`.
- **Google**: pacote oficial `googleapis` ou chamadas HTTP diretas com `google-auth-library` para o OAuth.
- **Planilhas**: `papaparse` para CSV e `exceljs` para XLSX.
- **LLM para os resumos**: atrás de uma interface `ProvedorLlm`, com duas implementações escolhidas por `LLM_PROVEDOR`: `anthropic` com o SDK oficial `@anthropic-ai/sdk`, e `mock`. A interface permite acrescentar outro provedor depois sem mexer nos serviços. O modelo vem de `LLM_MODELO`. Confira na documentação oficial do SDK os nomes de parâmetros e o formato de saída estruturada antes de implementar.
- **Fila de jobs**: implementada no próprio PostgreSQL, na tabela `trabalhos`, com `FOR UPDATE SKIP LOCKED`. Não use Redis nem biblioteca de fila externa.
- **Agendamento**: `node-cron` para as tarefas recorrentes, com trava na tabela `execucoes_agendadas` para não rodar duas vezes, inclusive com mais de uma instância do servidor.
- **Validação**: `zod` em todas as entradas da API e em toda resposta estruturada do LLM.
- **Testes**: `vitest` no servidor e no web. No web, `@testing-library/react` com `jsdom` para testar componentes e formulários. Sem testes ponta a ponta com navegador no MVP.
- **Dependências auxiliares já aprovadas**, sem precisar perguntar: `@fastify/multipart` para o upload, `nodemailer` para o SMTP, `cross-env` para definir `AMBIENTE_APP` e `NODE_ENV` também no Windows, `dotenv` para carregar o arquivo de ambiente, `tsx` para rodar TypeScript em desenvolvimento, `pino-pretty` para logs legíveis em desenvolvimento, `@fastify/helmet` para os cabeçalhos de segurança, `@vitest/coverage-v8` para o limiar de cobertura, `@vitejs/plugin-react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `eslint` com `typescript-eslint`, `eslint-plugin-react`, `eslint-plugin-react-hooks` e `eslint-plugin-jsx-a11y`, `prettier`, `stylelint`, `tailwindcss` e os pacotes `@types/*` necessários. As regras que essas ferramentas fazem cumprir estão em `padroes-de-engenharia.md`. Para Windows-1252, use primeiro o `TextDecoder` nativo do Node; se não bastar, `iconv-lite`. Qualquer outra dependência fora da stack continua exigindo minha aprovação.
- **Site público (fase 13)**: workspace próprio `site/`, com a landing e o blog, com HTML pré-renderizado no build por `react-dom/server` e o modo de renderização no servidor do Vite, servido pelo mesmo Fastify por `Host`, sem servidor de renderização nem framework novo. Reaproveita só os estilos, os componentes base e o `lib` do `web/`, em uma direção. Artigos em Markdown no repositório. O leitor de Markdown e o de frontmatter são dependências novas, declaradas só no `package.json` do `site/`, que exigem minha resposta, com sugestão de `react-markdown` e `gray-matter`.
- **Monorepo simples**: pastas `server` e `web` na raiz (e `site`, na fase 13), com um `README.md` explicando como rodar. Em produção, o próprio Fastify serve o front-end compilado com `@fastify/static`, num único processo, o que também garante que os cabeçalhos de segurança valham para as telas.
